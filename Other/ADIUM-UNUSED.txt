ADIUM-UNUSED - inventory of code that is still in the tree but no longer reachable.

Files that can carry a comment are marked in place with the token ADIUM-UNUSED:

	git grep -In ADIUM-UNUSED

This file lists the rest: binaries, project file entries and localizations, where an
in-place marker is impossible or would not survive.


ZEPHYR
======

Why it is dead: the registration in
Plugins/Purple Service/CBPurpleServicePlugin.m is commented out; +registerService is the
only path that makes a service reachable, so no Zephyr account can be created, loaded or
connected. It is broken beyond that anyway: zhm is in no copy-resources phase, so
-[ESPurpleZephyrAccount ...] would look it up and get nil, and the binary is i386/ppc.

Existing accounts: harmless. AdiumAccounts.m keeps entries whose service is unknown in
unloadableAccounts and writes them back unchanged - no UI entry, no error, no data loss.

Marked in place (11 files, all under Plugins/Purple Service/):
	ESZephyrService.h / .m
	ESPurpleZephyrAccount.h / .m
	ESPurpleZephyrAccountViewController.h / .m
	DCPurpleZephyrJoinChatViewController.h / .m
	PurpleDefaultsZephyr.plist
	Resources/Base.lproj/ESPurpleZephyrAccountView.xib
	Resources/Base.lproj/DCPurpleZephyrJoinChatView.xib

References in living code, marked in place, to be removed in the same step:
	Plugins/Purple Service/PurpleServices.h        #import "ESZephyrService.h" - build breaks if it stays
	Plugins/Purple Service/SLPurpleCocoaAdapter.m  prpl-zephyr branch in serviceClassForPurpleProtocolID()
	Source/AdiumOTREncryption.m                    prpl-zephyr entry in -prplDict
	Other/XtrasCreator/AXCServiceIconPackDocument.m  "Zephyr" icon pack entry (tool, not in Adium.xcodeproj)
	Resources/Service Icons/Aqua.AdiumServiceIcons/Icons.plist  "Zephyr" in all three dicts

Not markable, delete by hand:

	Binaries
		Plugins/Purple Service/zhm                (i386/ppc, in no build phase)
		Other/zephyr-mac.tar.bz2                  (referenced nowhere)
		Resources/Service Icons/Aqua.AdiumServiceIcons/zephyr.png
		Resources/Service Icons/Aqua.AdiumServiceIcons/zephyr-small.png
		Careful: the "Stress Test" key in Icons.plist (Interface-Large, Interface-Small)
		points at the same two images. Drop that key too or the reference dangles. In the
		List dict "Stress Test" uses yahoo-small.png and is not affected.

	Adium.xcodeproj/project.pbxproj  (Xcode rewrites this file and drops foreign comments,
	so it cannot be marked)
		grep -n 'ephyr' Adium.xcodeproj/project.pbxproj   -> 105 lines
		grep -nw 'zhm'  Adium.xcodeproj/project.pbxproj   ->   2 lines
		All of them belong to the AdiumLibpurple target: 11 PBXBuildFile, 11 PBXFileReference
		for real files, the "Zephyr" PBXGroup plus its child reference in "Services", and
		4 headers / 3 resources / 4 sources build phase entries. The 4 headers are exported
		Public; no in-tree consumer.
		58 of the fileRefs are localized .nib paths (29 languages x 2 views) that are pure
		orphans: no PBXVariantGroup, no build phase entry, each ID occurs exactly once.
		They can be deleted independently of the Zephyr decision.
		The 2 zhm lines are orphans as well: fileRef plus group reference, no copy phase.

	Localizations - Plugins/Purple Service/Resources/<lang>.lproj/Localizable.strings, 29
	languages, marking them individually would make the files unreadable:
		"The Zephyr Host Manager reported an error #%d: %@"
		"zhm Failure"                (only it.lproj)
		"Export to .zephyr.subs"     (missing in en.lproj)
		plus the comment /* zhm is the Zephyr Host Manager ... */ above them
		Sources of these strings: ESPurpleZephyrAccount.m, ESPurpleZephyrAccountViewController.m

	License.txt - the zhm MIT license block becomes obsolete once zhm is gone.
	ChangeLogs/Changes.txt is history and stays.

	prpl-zephyr itself is compiled into libpurple. Removing it means dropping "zephyr" from
	PROTOCOLS in Dependencies/phases/build_purple.sh and rebuilding the library. The same
	build already produces prpl-aim, prpl-icq, prpl-oscar and prpl-gtalk, which Adium does
	not bind either.
